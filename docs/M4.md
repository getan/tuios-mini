# M4: the embedded core, isolated from the standalone product

M4's goal is one `golder` binary carrying the agent, the browser host and the
workspace. The workspace is the part that lives here: `mini` starts a daemon in
the host's process, and `mini/control` is how the host drives it.

This stage fixes the ways an embedded daemon still behaved like the standalone
product: it read the machine's tuios harness directory, it bound the product's
extra sockets, it closed panes one at a time, and its unclassified log lines went
to whatever standard logger the host happened to have.

## 1. The profile: `session.ProfileLocalOnly`

`session.DaemonConfig.Profile` selects what a daemon runs. The zero value is
`ProfileStandalone`; `mini` sets `ProfileLocalOnly`.

| Service | Standalone | Local-only | Where it is gated |
|---|---|---|---|
| daemon socket, pid file, state dir, resurrection | on | on | core |
| sessions, windows, panes, history, control verbs | on | on | core |
| control socket for a TUI client | on | on | core |
| explicit agent reports (`set-agent-state`, metadata, `get-agent-state`) | on | on | core |
| federation `.link` / `.link-human` sockets | on | **off** | `Daemon.Start` |
| federation supervisors, host fleet, transfer journal | on | **off** | `Daemon.Start` |
| config watcher for `[hosts]` | on | **off** | `Daemon.Start` |
| herdr protocol socket and herdr link | on | **off** | `Daemon.NewDaemon`, `Daemon.Start` |
| ssh-agent following (`agent-*.sock` links) | on | **off** | `Daemon.NewDaemon` (`SetSSHAgent`), `Daemon.Start` |
| display following (`*-wayland-*.sock` links) | on | **off** | `Daemon.NewDaemon` (`SetDisplay`), `Daemon.Start` |
| hook event runner | if `[hooks]` | **off** | `Daemon.Start` |
| herdr plugin processes and their event follower | if `[plugins]` | **off** | `Daemon.NewDaemon`, `Daemon.Start` |
| push notifier (Inbox → phone) | if `[notify]` | **off** | `Daemon.Start` |
| transcript file watcher (fsnotify) | on | **off** | `Daemon.NewDaemon` |
| agent auto-detector | if configured | if `Config.AgentDetection` | `Daemon.NewDaemon` |
| checkpoints | if configured | if `Config.AgentCheckpoints` | `Daemon.NewDaemon` |
| `cleanupLoop`, `listingNotifier`, stall monitor | on | on | core housekeeping |

The profile gates services that the product runs by default. It does not
silently override something the caller explicitly asked for: an embedded
workspace that sets `AgentDetection` still gets the detector, and `Checkpoints`
still takes checkpoints. The three exceptions are forced off because they are
forwarding or protocol surfaces of the product rather than features of a pane:
the herdr protocol, ssh-agent following and display following.

Tests: `internal/session/daemon_profile_test.go` (listeners and files, both
profiles), `mini/isolation_test.go` (`TestMiniBindsNoProductSocket`,
`TestMiniKeepsExplicitAgentReports`).

## 2. Harness manifests

`newAgentMatcherFrom` takes a `harnessSource`:

- `harnessSourceUser` — the standalone default: bundled manifests plus
  `harness.UserDir()`, which follows `TUIOS_HARNESS_DIR` and
  `XDG_CONFIG_HOME/tuios/harnesses`.
- `harnessSourceBundled` — only the manifests compiled into the binary.
- `harnessSourceDir` — exactly one directory the caller names.

`DaemonConfig.HarnessDir` selects the third, `DaemonConfig.BundledHarnessesOnly`
the second, and the zero value keeps the first. `mini.Config.HarnessDir` is the
caller's folder; empty means bundled-only. A workspace therefore never reads the
harness rules of a standalone tuios on the machine.

Tests: `internal/session/agent_matcher_source_test.go` (registry contents),
`mini/isolation_test.go` (`TestMiniIgnoresTheUserHarnessDirectory`,
`TestMiniReadsItsOwnHarnessDirectory`; a planted manifest that cannot load is
visible in the workspace's own log exactly when the directory is read).

## 3. Shutdown cost

`PTY.Close` is three steps: `closeRequest` (cancel, unsubscribe, SIGTERM),
`closeAwait` (up to `ptyCloseGrace`, then kill), `closeRelease` (emulator,
winsize, descriptor). `Session.Stop` used to call `Close` per pane in sequence,
so a session cost one 100 ms grace per pane whose process ignored SIGTERM: ten
panes held shutdown for a second. It now calls `closePTYs`, which asks every pane
to leave before waiting on any, so the panes share one grace.

No callback runs in `closePTYs`, and the session's pane lock is held exactly as
before, so nothing re-enters the session while it closes panes. The socket is
still unlinked last in `Daemon.shutdown`; this change does not move any cleanup
after the unlink.

Test: `internal/session/pane_close_batch_test.go` (five panes that ignore
SIGTERM; Stop must finish within 1.5 graces rather than 5).

Still linear: `Manager.Shutdown` stops sessions one after another, so a daemon
with several sessions pays one grace per session. `mini` starts one session, so
this is not on the workspace's path today.

## 4. Log routing

`Daemon.logLine` and `Daemon.warnf` are the two per-daemon paths:

- With `DaemonConfig.LogSink` set (what `mini` does when `Config.LogFile` names
  a file), the line goes to the process ring buffer, the debug output at the
  configured level, and the daemon's own sink. It does **not** go to the
  process-wide daemon log file, and nothing calls `log.SetOutput`.
- Without a sink (the standalone daemon), both fall back to `logRaw` /
  `log.Printf`, which is the logger `InstallDaemonLogging` installed. Behaviour
  there is unchanged.

All product-service call sites that have a `*Daemon` in hand now go through
`warnf`: federation, herdr, plugins, notify/webpush, grants/config reload,
resurrection, session restore, history load, frame budget, accept loops.

Residual use of the standard library logger, deliberate:

| Site | Why it is not routed |
|---|---|
| `session.debugLog` | `TUIOS_DEBUG_INTERNAL` diagnostics, called from free functions with no daemon handle |
| `Session.createPTY` "configured shell not found" | `Session` has no daemon handle; the warning is about the pane's own spawn |
| `TUIClient.pasteHoldExpired` | client-side line, not daemon state |
| `newAgentMatcherFrom`, `logLine`, `warnf` fallbacks | the fallback *is* `log.Printf` for a daemon without a sink |

These print to the host's standard logger only if the host set one, which for
an embedded daemon is the host process's own output. Fixing them needs a logger
threaded through `Session`/`TUIClient`, which is a wider change than this stage.

## 5. Import boundary

`mini` does not link the TUI, the browser host or any command:

```text
internal/app, workspace, cmd/tuios, cmd/tuios-web, cmd/tuios-mini,
e2e/tui, charm.land/bubbletea, charm.land/wish, charm.land/ssh
```

It still links the product's own packages, and the profile only decides what
runs:

```text
internal/agentproto, federation, ghpr, herdrcli, herdrplugin, hooks,
integration, pushnotify, review, risk, shimlink, tape, transcript,
transcriptview, worktree
```

and, through the daemon's own code, `charm.land/lipgloss/v2`,
`github.com/charmbracelet/ultraviolet`, `tuios.dev/vt`, `tuios.dev/shot`,
`tuios.dev/swatch` and `tuios.dev/progstatus`.

So a local-only daemon is **not** a source-level removal of the standalone
product. The services are not started; the code is linked. Shrinking the binary
further means decoupling `internal/session` from federation/plugins/hooks, which
has not been done.

Tests: `mini/imports_test.go` pins both halves, with a negative control that
applies the same rule to `cmd/tuios` and requires it to flag the TUI.

## 7. A workspace's panes arrange their own session

A workspace starts its panes on the strict default of
`[agents.permissions]`: `read`, `write` and `fan`. Those grants reached every
verb that reads or types into the pane's own session, but not the verbs that
arrange it. `new-window`, `close-window`, `focus-window`, `move-window`,
`set-window` and `resize` are `scopeDeny` in `verbScopes`, so a pane without
`admin` was refused them by `checkGrants` and a connection that restricted
itself was refused them by `checkScope`. Golder's workspace could therefore not
open a pane for a browser or a build, rename one, focus one, move one to another
workspace, resize one or close one, although each of those acts only on the
session the caller is already in.

`internal/session/local_control.go` admits the six for a **local-only** daemon
(`d.localOnly()`), as a new scope kind, `scopeLayout`: an act on the panes of the
caller's own session, which needs the `write` grant and is refused to a
read-only caller. `verbScopes` is not touched, so the standalone product's
policy for its panes and for restricted connections is exactly what it was, and
`grantKind` still answers `scopeDeny` for the six. Both layers ask
`d.layoutKind`, so `checkGrants` (a pane's grants) and `checkScope` (a restricted
connection) cannot drift apart, and both hold the call to the caller's own
session through `holdToPane`.

Narrower than every other `own` row:

| Held away | How |
|---|---|
| another session | the reach is the caller's own session only — not the fan group `read` reaches, not a session it launched (`sessionIsOwn`, not `sessionInScope`) |
| another session's window, by move | `move-window`'s `to_session` is refused outright in both layers (`layoutParamsWhy`); it is the one parameter `holdToPane` does not read |
| another machine | `holdToPane`'s host rule refuses `new-window` with a `host` |
| a wider pane | `new-window`'s `grants` go through `launchGrants`, which a pane cannot talk past |
| a pane that holds more | `close-window` closes only panes holding nothing the caller does not, as typing refuses to type into one (`closeRefusal`); a pane may always close itself |
| everything else `admin` owns | `kill-session`, the options, the listings across sessions, `close-workspace`, `set-layout`, `split-window`, `popup`, `select-workspace`, the file and transfer verbs, the link verbs, the client protocol: all still `scopeDeny` |

Tests: `internal/session/local_control_test.go` asks both layers directly, on a
daemon built in memory with no PTY, for the six verbs under `write`, under
`read`, under no grants and under the standalone profile, for a foreign session
and the fan group, for `to_session`, another machine, the grants a new pane may
be given and the pane `close-window` will not close, and for the verbs that stay
refused. `mini/local_control_test.go` runs the same policy through a real daemon
and `mini/control`: a pane's connection opens, renames, focuses, moves, resizes
and closes in its own session; a foreign session, another machine, `to_session`,
every admin verb, a read-only connection and a pane narrowed to `read` are
refused; and a pane holding more than the caller cannot be closed.

## 8. Not done

- `Manager.Shutdown` still stops sessions serially (one grace per session).
- The four residual standard-logger sites above need a logger threaded through
  the session/client types.
- Plugin and federation verbs still exist on a local-only daemon; they answer
  from an empty table and an unstarted host rather than refusing. A workspace
  that wants them refused has to say so.
- `internal/app`, `workspace` and the CLIs remain in the repository and are
  imported by each other; they are outside the embedding, not deleted.
