# M1: the embeddable core

M1 is the first slice of tuios-mini: a daemon that starts as a library, creates
one session with no TUI, and speaks exactly the control verbs golder uses. The
rest of the tuios product is still in the tree; pruning it is a later step.

## What M1 adds

| Path | Purpose |
|---|---|
| `mini/server.go` | `Start(ctx, Config)` / `Stop()`; owns the daemon and the session |
| `mini/client.go` | The JSON-line control client used by the tests and the CLI |
| `cmd/tuios-mini` | A foreground daemon with one socket, one session, no TUI |
| `mini/server_test.go` | Real PTY + real daemon coverage of the 15 verbs |
| `scripts/check-golder.sh` | Runs golder's live client test against this daemon |

`mini.Start` installs no signal handlers: the embedding process owns its
signals. `DisableSignalHandling` in `DaemonConfig` makes that explicit.

## The contract

Golder's `internal/tuiosctl` uses these verbs, and M1 covers each one on a real
daemon:

| Verb | M1 test |
|---|---|
| `list-windows` | `TestMiniDaemonVerbs` |
| `get-window` | `TestMiniDaemonVerbs` |
| `new-window` | `TestMiniDaemonVerbs` |
| `close-window` | `TestMiniDaemonVerbs` |
| `focus-window` | `TestMiniDaemonVerbs` |
| `move-window` | `TestMiniDaemonVerbs` |
| `resize` | `TestMiniDaemonVerbs` |
| `set-window` | `TestMiniDaemonVerbs` |
| `send-text` | `TestMiniDaemonVerbs` |
| `send-keys` | `TestMiniDaemonVerbs` |
| `capture-pane` | `TestMiniDaemonVerbs` |
| `screenshot` | `TestMiniDaemonVerbs` |

`new-session` is exercised by `mini.Start`; `hello` by every dial.

## Running it

```sh
# The core contract, on a real PTY.
go test ./mini -v

# The daemon as a process, plus golder's own client against it.
./scripts/check-golder.sh
```

`check-golder.sh` expects the golder checkout next to this one. Set
`GOLDER_DIR` otherwise. It builds `cmd/tuios-mini`, starts it on a short
`/tmp` socket, and runs `TestLiveMiniDaemonContract` in golder.

## Deliberate limits

- **No TUI.** `cmd/tuios-mini` is a headless daemon. Until M3, the person still
  runs tuios for panes; M1 proves the control path.
- **No pruning yet.** The fork still contains the upstream product surface.
  M1 is the boundary and the regression net, not the diet.
- **Module path.** The module is still `github.com/Gaurav-Gosain/tuios`, so
  the fork can merge upstream until the package moves into golder.
- **`restrict-connection` scope.** The tests use `scope all` with `read_only`,
  because a process outside a pane cannot present a pane token. Golder's
  production path uses `scope own` plus `TUIOS_PANE_TOKEN`; that path is
  unchanged and is covered by golder's own tests.
- **`run` needs OSC 133.** The test shell in `mini/testdata/integrated-sh`
  emits the marks; a plain shell still returns `no_shell_integration`.
- **`screenshot` uses the daemon renderer.** The test asserts a non-empty PNG;
  pixel goldens belong to the renderer's own suite.
