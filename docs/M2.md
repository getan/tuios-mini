# M2: boundary, permissions, shutdown, first pruning

M2 turns the M1 demo into a core that can be depended on and cut down:
the wire client is its own package, the permission boundary has a real test,
closing a pane asks before it kills, and the first CLI-only packages are gone.

## 1. The boundary: `mini` and `mini/control`

`mini/control` holds the JSON-line client. It imports only the standard
library, so a caller can speak the protocol without linking the daemon, the
PTYs or the terminal emulator. `mini` keeps the daemon lifecycle and imports
`mini/control`; neither exposes a type from `internal/session`.

This is the external boundary M2 promised. The internal split of the 108k-line
`internal/session` package into `pty`, `window`, `daemon` and `control` is
**not** done here: it is a physical refactor with a large regression surface,
and M2 stops at a stable, tested seam instead of pretending otherwise.

## 2. The permission contract

`TestMiniScopeOwnRequiresThePaneToken` reads the pane's own
`TUIOS_PANE_TOKEN`, narrows a second connection with
`restrict-connection {scope: own, pane_id, pane_token}`, and proves:

- the caller's session is still readable and writable;
- another session's `list-windows` and `send-text` answer `forbidden`.

This is the same path golder uses in production. The previous M1 test covered
`scope all` plus `read_only`; it did not prove the token.

## 3. Closing a pane

`PTY.Close` now asks the pane's process to leave with SIGTERM, waits up to
100 ms for `monitorExit` to observe the exit, and only then sends SIGKILL
and closes the terminal. On Windows the request is `Kill`, since there is no
SIGTERM.

`TestMiniCloseSendsSIGTERMFirst` starts a shell that installs a TERM trap,
waits for a ready file, closes the pane, and asserts the trap wrote its file.
The 100 ms bound is deliberate: earlier versions used 2 s and 500 ms and pushed the
full `internal/app` suite past its 6-minute ceiling. The bound is a ceiling,
not a promise; a program that ignores SIGTERM still loses its pane.

The signal goes to the pane's own process, not a process group. A shell that
keeps a foreground child alive may still need the PTY close's SIGHUP, or a
later process-group policy, to take the child down.

## 4. The first pruning

Removed, with their commands, tests and dedicated CI:

| Path | Lines | Why |
|---|---:|---|
| `internal/webshell` | 4,018 | in-memory shell for the browser tour |
| `internal/learn` | 1,471 | lesson state for the browser tour |
| `cmd/tuios-wasm` | 303 + assets | browser tour entry point |
| `internal/guibridge` | 3,526 | native-renderer transport |
| `internal/mcp` | 2,070 | MCP server facade |

The change is **72 files, +295 / -12,973 lines**. `justfile` lost the `learn`
and `wasm-check` targets, `learn-web.yml` is deleted, and the ghostty job no
longer watches the deleted trees.

There were no optional submodules to cut at v0.10.1: `go.work` holds only
`progstatus`, `shot`, `swatch` and `vt`, and the daemon needs all four. The
sketch/plot/loom/tml modules arrived after this baseline.

`go mod tidy` left `go.mod` and `go.sum` unchanged: the removed packages did
not own dependencies the rest of the tree still needs.

## 5. Verification

```text
go build ./...                                   pass
go vet ./mini ./cmd/tuios-mini                   pass
go test ./mini ./internal/session                pass
go test ./cmd/tuios -skip 'TestShippedBinary*|TestFuzzBinary*|TestComposerImports*'   pass
go test ./internal/app                           pass (203s, timeout 6m)
scripts/check-golder.sh                          pass
```

`internal/app` takes about 3.4 minutes, and `TestMoveStands` passes in
isolation (5s). The 100 ms close bound keeps the full suite well under the
6-minute CI ceiling.

The three skipped `cmd/tuios` tests shell out to `go list -deps`; in this
sandbox the nested Go command waits on module resolution, with or without
network. They are import-graph checks unrelated to M2 and run in CI.

## 6. What is deliberately still here

- `internal/app` (the TUI), `internal/tmuxcompat`, `internal/federation`,
  `internal/integration`, `internal/review`, `internal/risk`, `internal/tape`,
  `internal/herdrplugin` and the workflows. Removing them needs decoupling,
  not a blind delete.
- `internal/app/learn_mode.go` and comments that name the deleted packages:
  they are UI behavior or prose, not dependencies. Clean them when the TUI is
  reshaped in M3.
- The module path is still `github.com/Gaurav-Gosain/tuios`.
