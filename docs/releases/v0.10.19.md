# tuios-mini v0.10.19

Correct the VT header differential fuzz oracle without changing the runtime VT
library, its module path or its v0.2.0 pin.

The upstream-owned `vt/FuzzKittyHeader` compared the entire command struct,
including private PNG payload-prefix bookkeeping. The minimized `f=100;0`
case differs only in a nil versus empty private prefix after payload handling;
its exported control keys, error response and echo classification agree.

The equivalent campaign now runs as `internal/vtcontract/FuzzKittyHeader` in
this fork's root module. It retains all original seeds plus the failing corpus
artifact, and still checks parse acceptance, owed error replies, echo status,
payload-error direction, absence of header-only image decoding, object names
and every exported control key. A mutation guard changes each public control
field in turn and requires the comparison to detect it, including fields a
future VT release adds.

The retained corpus fails with the original whole-struct comparison and passes
with the corrected oracle. CI replaces only this campaign's location; no
protocol assertion or other VT campaign is disabled. The original nested VT
files are unchanged, keeping the standalone library pin consistent. Golder's
separate polling-fixture race correction ships in its own release.
