# tuios-mini v0.10.20

Two CI defects from the 2026-10-29 reruns, both test/CI-layer; no runtime
behavior changes.

## Fuzzer toolchain

`progstatus/FuzzParse` failed with `context deadline exceeded` at exactly the
60-second `-fuzztime` boundary and uploaded no failing input. That is
[golang/go#75804](https://github.com/golang/go/issues/75804): Go 1.26 cancels
workers only through a child context, so expiry can surface as a target failure
while a crash is being minimized. The fix is in Go 1.27 (and later 1.26
releases, not yet available); the Fuzz workflow now uses Go 1.27.3 instead of
the module's 1.26.10 toolchain. The module's own floor and pins are unchanged,
and a local 60-second run of that target passes.

## Daemon verb regression

`mini/TestMiniDaemonVerbs` failed under `-race` with "the shell ... is not at
its prompt". `wait-for window-output HELLO-MINI` also matches the command's own
echo on the prompt line. The test then waited for `at_prompt`, which is still
true before the shell reports command-started, so `run` could race that mark.
The test now first waits for `command-finished` at the baseline sequence and
then for the following prompt. No daemon behavior changed: `run` correctly
refused a pane that was executing a command. Eight consecutive real-PTY race
runs pass.
