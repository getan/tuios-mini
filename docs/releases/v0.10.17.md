# tuios-mini v0.10.17

SSH clients use a reduced, client-owned rendering profile by default: ASCII
chrome and file markers, a small plain welcome, flat decoration, no cosmetic
motion/hover or background dock jobs, and a 10 Hz background pane-output cap.
Input and pane contents remain intact, as do application-requested mouse
events. Local and browser clients do not inherit the SSH profile accidentally.

Reload/settings cannot remove the transport cap or persist this policy into
the user's configuration. `TUIOS_SSH_FULL_UI=1` restores the full UI for a local
process launched through OpenSSH, for controlled comparison.

See [failure inventory, implementation and real OpenSSH measurements](../SSH_REDUCED_RENDERING.md).
No claim is made that a production one-minute stall or broken-link terminal
mode persistence has been completely diagnosed by reducing rendering.

## Nightly CI repairs

Retain and fix the three failing fuzz artifacts: tiny bordered panes painting
past their rectangle, malformed-escape clipping losing a cell, and overflowing
unknown TOML values bypassing default seeding. The guest-cell oracle now uses
actual visible content space rather than the VT's synthetic 1x1 minimum.

Repair the SSH graphics fixture's shared SHM names and split-marker detector,
and wait past the pre-config nest probe in the workspace isolation fixture.
Queued pane-mark pushes no longer masquerade as attach replies; rename/file
text follows the owning model rather than stale overlay state. ASCII SSH
decoration retains Unicode filenames and typed names.

The full root-module race suite passed, alongside final targeted regressions,
mutator smoke runs, build/vet and cross-build checks. The Linux native SHM
integration passed 3 consecutive eight-session runs. See [CI evidence and
negative controls](../CI_2026_10_28.md). No workflow tests were disabled or time
budgets widened to hide the failures.
