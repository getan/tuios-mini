# tuios-mini v0.10.18

Fix a data race found by the full Linux race rerun of v0.10.17:
`new-window --wait --keep-open` read a retained popup signal concurrently with
the PTY exit callback. It then overwrote that read with the live PTY's signal,
but an unused read is still a race.

Read the live PTY's mutex-protected signal when the PTY is available. Only
read retained fields when the PTY is gone, after its publication channel has
closed. No new lock, polling loop or timeout is introduced. The existing
daemon/PTY exit-status and killed-program regression remains the gate.

This includes v0.10.17's SSH rendering and original nightly-CI repairs. Already
published tags are unchanged. The additional finding is documented in the
[CI investigation](../CI_2026_10_28.md).
