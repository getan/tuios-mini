# v0.10.41 — Assign a pane to one Golder Agent

The pane context menu can now act as Golder's operator authorization surface.
When live top-level Golder sessions register beside this daemon, a pane menu:

- shows its current Agent controller and lease scope;
- lists only live, non-read-only Agents in the same session and workspace;
- grants control for the next action or the Agent conversation;
- revokes the current lease; and
- asks a second, cancel-first confirmation before transferring an occupied pane,
  naming both the old and new controller.

The integration uses a private daemon-adjacent registry shared with Golder.
Writes use the same process lock and atomic replace as Golder, and bind the lease
to the daemon instance, full pane ID, workspace, foreground and remote host hint.
The daemon still owns terminal state; Golder remains the enforcement point that
reviews each command and atomically consumes one-call leases.

Dynamic grant actions require a token carried only by direct menu selection and
are excluded from tape recording, so a project tape, keybinding or copied action
name cannot replay operator authorization. Agent, approval and kitty-browse panes
are not offered as targets. Tests cover candidate filtering, status, one-call
grants, transfer confirmation, revocation, SSH identity and replay refusal.

v0.10.42 follows with the same inter-process exclusivity on Windows: the shared
registry lock uses `LockFileEx`, and an abnormal process exit releases it with
the file handle just as `flock` does on Unix.
