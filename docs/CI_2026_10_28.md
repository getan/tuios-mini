# Scheduled CI failures on 2026-10-28

Both jobs ran commit `771f2b9` (v0.10.16), before the SSH reduced-rendering
changes. They are not dismissed as runner noise or fixed by skipping tests.

- [Fuzz #5, run 40675087549](https://github.com/getan/tuios-mini/actions/runs/40675087549)
- [Scheduled race suite, run 40665883309](https://github.com/getan/tuios-mini/actions/runs/40665883309)

## Fuzz findings: artifacts retrieved and replayed

1. **FuzzModel `6bc51b05eae1b3db`**: the CI worker hung/terminated during
   minimization. Replaying its bytes locally produces the real `guest-cells`
   finding: seven panes, host resized to 60x20, one bordered pane only one row
   tall. The VT requires at least a 1x1 grid, so the border renderer emitted
   three rows and painted into its neighbour. Tiny window boxes are now clipped
   to their allocated rectangle. A separate oracle error also claimed the VT's
   synthetic minimum cell was visible guest space even when borders used the
   entire pane. The oracle now checks actual visible content dimensions,
   skips only the undrawable pane, and still checks drawable neighbours.
   `TestCICrowdedPaneReplay` verifies the frame bounds as well as ownership. With
   the renderer fix removed it reports three rows in one/two-row rectangles.

2. **FuzzClipWindowContent `801bc117cca9cdbc`**: `ESC + U+0206 + 000`, cut
   three cells from the left, returned zero cells where one was expected.
   Cutting a malformed escape can turn the first retained character into its
   final byte. Finished clipped rows now fill missing source-owned cells only
   after a reset, in addition to the existing upper width bound. The corpus
   case failed on the old code and passes with the fix.

3. **FuzzConfigSaveRoundTrip `23ed3a2061fd2cf5`**: an unknown TOML key held
   an integer outside the signed 64-bit range. Struct decoding skipped the
   value, but the later generic-table parse failed and silently bypassed
   default seeding. Saving then changed other settings on reload. Validate the
   complete TOML document, including unknown values, before accepting it.
   The invalid integer is now rejected rather than loaded inconsistently.

All three original corpus files are retained in `testdata/fuzz/`. Reproduce:

```sh
go test ./internal/app ./internal/config \
  -run '^(FuzzModel|FuzzClipWindowContent|FuzzConfigSaveRoundTrip)$' -count=1
go test ./internal/app -run '^TestCICrowdedPaneReplay$' -count=1
```

## Scheduled race-suite failures

- **TestARealClientKeepsItsStateInItsOwnTree** checked glyph selection after
  *any* PTY output. The nest probe is written before loading configuration, so
  this observed the default set during legitimate initialization. The fixture
  now waits for alternate-screen entry, carrying its marker across reads;
  this happens after model/scoped configuration construction. Isolation and
  restoration assertions remain unchanged.

- **TestSSHKittyShmDoesNotKillSession** failed to start one graphics flood
  (`graphics=false text=true`). Four sessions shared each script's SHM names,
  but a terminal consumes/unlinks a `t=s` object: sessions could delete each
  other's inputs. Give all eight sessions distinct names and two rotating
  buffers each, keeping their total below a 64 MiB SHM mount. Also carry the
  graphics APC introducer matcher across SSH reads; a per-read `Contains`
  misses a split `ESC _ G`. `TestFloodGraphicsMarkerAcrossReads` fails with the
  previous detector and passes with the streaming one. The eight-session
  Linux native integration passed three consecutive runs. Neither the session
  count, actual-graphics gate, transport-survival gate nor watch duration is
  weakened. No time budget is widened in the workflow.

## Additional full-local-race findings

- Reattaching a TUI client could mistake a queued pane-mark push (message 70)
  for its attach reply. Attach now uses the existing request/reply helper;
  its pre-reader path ignores non-reply message types. The attached snapshot
  establishes the new session state instead of carrying old pushes across.
- Rename append/dialog paths inherited the last rendered client's global
  overlay ASCII mode. Synchronize to the owning model before their text gate,
  retaining Unicode names for normal local clients after an SSH/ASCII view.

Full-suite and upstream rerun results belong to the release verification, not
to the fact that these targeted reproductions passed. Linux native targeted

## Follow-up: retained popup signal (v0.10.18)

The [30-second-per-target Fuzz rerun](https://github.com/getan/tuios-mini/actions/runs/40732880021)
passed all jobs on v0.10.17, as did ordinary Linux/Windows unit jobs. The
[full Linux race rerun](https://github.com/getan/tuios-mini/actions/runs/40732880004)
then exposed a separate real race in unchanged popup-exit code:
`TestNewWindowKeepOpenWaitReportsTheExitStatus`, read in
`verb_handlers.go:421`, write in `popup_wait.go:122`.

`new-window --wait` eagerly read `exitStatus.signal` while the exit callback
was still publishing it, even though the live PTY branch immediately replaced
that value. A read that will be overwritten is still a data race. Waiting for
the keep-open exit note does not order completion of this separate callback.

The reply now takes the live PTY's mutex-protected signal when available.
Only the removed-PTY branch reads the retained signal, after receiving from
its publication channel. No lock, timeout or retry loop is added. The same
existing real-daemon/PTY regression passed 100 consecutive local race runs
after the repair; the CI stack is the negative control (30 local pre-fix
repetitions did not reproduce the scheduling window).

Already published v0.10.17 is preserved. This follow-up is a new patch tag,
not a force-moved release or a skipped race test.

## Follow-up: VT header oracle (v0.10.19)

The subsequent [Fuzz run](https://github.com/getan/tuios-mini/actions/runs/40738060821)
found `FuzzKittyHeader/ea9ca4fd287ee68d`, input `f=100;0`. Local replay confirmed
identical control keys, error responses and echo classification; whole-struct
reflection also compared private PNG-prefix payload state (nil versus empty).

The maintainer approved keeping the runtime VT module/path/pin unchanged.
CI now runs the equivalent differential target in `internal/vtcontract`,
owned by this root module. All original seeds and protocol assertions remain:
parse acceptance, error responses, echo classification, payload-error direction,
header-only decoding prohibition and object names. The control comparison
enumerates every exported field rather than private payload implementation
details. A guard mutates each of the 26 public control fields and requires
every change to be detected, including new fields in future library releases.

The original comparison failed on the retained corpus before the correction;
the corrected target and guard passed under race detection. A local 60-second
mutation campaign passed 5,262,173 executions. No file under `vt/`, runtime
dependency pin or module path is changed. Only this campaign's CI location is
replaced, not its protocol coverage or the other VT campaigns.
