# M3 stage 1: host detection, namespace, workspace mode, tmux removal

M3's full goal is one `golder` binary that carries the agent, the workspace
and the browser host, with no separate installs. That needs the retained TUI
and kitty-browse moved behind importable packages, which is a repository-level
refactor. This stage lays the packaging foundation and removes one whole
CLI-only subsystem.

## Done in this stage

### Host detection

`mini.DetectHost` reads the variables a pane receives and reports `tuios`,
`tmux`, `zellij`, `screen`, `golder-workspace` or `plain`. `Host.Nested`
marks the multiplexers. `GOLDER_WORKSPACE` wins over `TUIOS_ENV`: a pane in a
golder workspace also carries the tuios-style host contract.

### A namespace that is not tuios's

`mini.DefaultNamespace` returns the workspace's config, state, runtime, socket
and log paths under `golder/workspace`. None contains `tuios`. Two daemons can
run on one machine without sharing a socket, a config tree or a log.

### `tuios-mini workspace`

The CLI now has two modes:

```sh
tuios-mini daemon     # M1 harness: one socket, one session
tuios-mini workspace  # M3: host detection, own paths, no nesting by default
```

`workspace` resolves its socket and log from the namespace, sets
`GOLDER_WORKSPACE=1` for the panes it starts, and refuses to start inside
tuios/tmux/zellij/screen unless `--nested` is given. The readiness line now
carries `mode` and `host`.

### tmux compatibility removed

`internal/tmuxcompat`, the `tmux` / `tmux-shim` / `tmux-pane` commands and the
`argv[0]` tmux dispatch are gone. The daemon never imported them. This stage
removes **10,042 lines across 34 files** of CLI-only code and the tests that
covered it. The whole stage is **45 files, +260 / -10,269 lines**.

## Gap check: what full M3 still needs

| Gap | Why it is not in this stage |
|---|---|
| `golder workspace` in the golder binary | needs the TUI extracted into an importable package, then a real module dependency from golder |
| kitty-browse absorption | separate 18.5k-line module; needs a public browser-host package and the pane rendering path |
| `internal/session` physical split | 108k-line refactor; M3 stage 2 |
| federation, plugins, hooks | session-coupled (federation alone touches 19 session files); needs decoupling before deletion |
| review / worktree / fan | the packages are imported by `internal/app` and `internal/session`; deleting the commands would not shrink the binary |
| module path `github.com/Gaurav-Gosain/tuios` | rename when the code moves into golder (M4) |

So M3 is **not** complete: this is the first stage. The next one should split
`internal/session`, then extract the TUI behind a public `workspace` package.
